## What shipped

`code/evaluation/usage.py` reads the usage log, the request file, and a
price table, then writes `evaluation/usage_report.md`. A model the price
table does not carry makes the run fail, so a missing price can never appear
as a cost of zero. Prices come from the Anthropic price list on 2026-10-25.

The measured run: 85 calls, 2 models, 169,948 input tokens, 70,053 output
tokens, 240,001 tokens total. That is 463.3 tokens per request across the
518 requests, an estimated $0.7039 in total and $0.0014 per request.

`README.md` is rewritten for this solution. It states the setup, the single
run command, the stage table, every test command, and the packaging command.

`code/package.py` builds `code.zip` and then reads the archive back. It
fails on an excluded directory, an excluded file, a nested archive, a
missing required file, or a credential in any text file. The archive holds
30 files: `README.md`, `code/`, `evaluation/`, and `docs/`.

## One ambiguity the user must decide

The contract says to sort `output.csv` by `case_id`. Two readings differ.

A string sort gives `case_100` before `case_33`. That is the literal reading
of a string column, it is what `code/evaluation/main.py check` enforces, and
`dataset/sample_output.csv` is consistent with it because those ids are zero
padded.

A numeric sort gives `case_33` first. That is the order of
`dataset/deletion_requests.csv` itself, which runs from `case_33` to
`case_550` in numeric order.

The shipped file uses the string sort. The scorer keys rows by `case_id`, so
the order changes nothing in our own measurement. It matters only if the
grader compares row by row. The decision is recorded here rather than made
silently.
